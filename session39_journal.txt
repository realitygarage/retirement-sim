--- DIAGNOSIS (v5.7.0) ---

Ran a scratch Node script (diag_surplus_tmp.mjs, deleted after use) against
engine.js's buildMonthlyScenario directly with default params, scanning
every monthly row across the full 20-year horizon for the max afterBuckets/
surplus/combinedSweep value -- found nothing above ~$1,100/mo anywhere. The
screenshot's visible chart data (Pension $3,300, mortgage $5,510, etc.)
also matched default-scenario values almost exactly. That ruled out "the
live scenario's own numbers are just big" as the explanation.

Traced surplusMax (App.jsx, feeds the chart's yDomain) and found the actual
bug: its `pinSweepMax` term scans EVERY pin in the `pins` array for sale/
sweep values, with no visibility filter --

  const pinSweepMax = pins.length>0 ? Math.max(...(chartData||[]).flatMap(
    r=>pins.map(p=>r[`pin_${p.id}_sweep`]||0)), 0) : 0;

Every other pin-aware read in the file (legend, chart lines, tooltips --
lines 1618/1625/1657/1676 pre-fix) filters through
`pins.filter(pin=>visiblePins.has(pin.id))` first. This was the one
holdout. The screenshot's legend showed only "Live" (no pin lines drawn),
consistent with the user having a saved pin toggled invisible -- its sweep
values (from whatever scenario it snapshotted, e.g. a lump-sum payoff/sale)
were still stretching the axis to ~90K even though nothing from it was
ever rendered.

Fix: filter to `visiblePins` in the `pinSweepMax` calc, same as everywhere
else, and add `pins`/`visiblePins` to the memo's dependency array (both
were missing -- the memo could have gone stale on pin add/toggle even
before this fix).

--- FOLLOW-UP (v5.8.0) ---

After the v5.7.0 fix, user flagged a second, unrelated issue on the same
chart: the breakdown table below it was sampling every OTHER year, not
every year. This wasn't a regression from the v5.7.0 edit -- it's the
long-standing default behavior for any chart without `annualTicks={true}`
(see the existing comment: "annualTicks charts... show every year; others
sample every other year to keep the breakdown table from getting too
wide"). The Free Cash Flow chart never had `annualTicks` set, so its table
always did this.

Couldn't just add `annualTicks={true}` to the FCF chart -- that flag also
forces the chart's own XAxis to label every year (`interval={annualTicks?
0:undefined}`), and the user explicitly said "the graph looks OK", only
wanting the table changed. Decoupled the two: added a new `annualBreakdown`
prop to the shared `Chart` component, independent of `annualTicks`, that
only affects the table's row sampling:

  const bdRows = (annualTicks||annualBreakdown) ? bdSource : bdSource.filter(...)

Applied `annualBreakdown={true}` to the FCF chart only. Its line chart's
tick density is untouched; its table now shows every year.
